# CLAUDE.md — Resilisense-FE (ResiliSense web app)

ResiliSense is a multi-tenant CSR/ESG assessment SaaS (ISO 26000 gap analysis, documentation assessment, stakeholder materiality, actions & KPIs, supply-chain ranking). This repo is the **frontend**. The API is `CetizionVerifica/CSR_BE`.

## Current state — read first

- The product is being **rebuilt from scratch** ("ResiliSense 2.0"). The plan, the design system and every module spec live in [`docs/revamp/`](docs/revamp/README.md) — the source of truth (mirrored identically in `CSR_BE`). Read `docs/revamp/README.md`, `02-design-system.md` and the module spec before building a screen.
- Until the scaffold PR lands, `main` still contains the **legacy** CRA 1 + antd 3 app (`src/`, committed `build/`). After Phase 0 it lives on the **`legacy`** branch (tag `legacy-v1`) and production deploys from there.
- Legacy code is **reference only** (screens, copy, domain content). Do not port its patterns: class components, redux-form, Apollo + axios + fetch mix, JWT in `localStorage`, business logic in components, inline styles, hard-coded English. Consult it with `git worktree add ../Resilisense-FE-legacy legacy` or `git show legacy:<path>`.

## Target stack (see `docs/revamp/01-target-architecture.md` ADR-008)

Vite 6 · React 19 · TypeScript strict · React Router 7 (data mode, lazy routes) · TanStack Query 5 + API client/hooks **generated by orval** from the backend's `openapi.json` · React Hook Form + Zod · Tailwind CSS v4 + shadcn/ui (Radix) + lucide-react · TanStack Table/Virtual · ECharts 5 (modular imports) · i18next (ICU) · date-fns + Intl · Vitest + Testing Library + MSW · Playwright + axe · Storybook 8.

## Commands (available after the scaffold PR)

```bash
npm ci
npm run api:sync        # fetch openapi.json from CSR_BE (pinned version) and regenerate src/api with orval
npm run dev             # http://localhost:5173 (proxies /v1 to http://localhost:4000)
npm run lint && npm run typecheck
npm test                # Vitest unit/component tests
npm run test:e2e        # Playwright (+ axe) against dev server with MSW or staging API
npm run storybook       # design-system workbench (a11y, RTL, dark-mode toolbars)
npm run i18n:extract    # update locales/en/*.json; CI fails on missing en keys
npm run build           # static build to dist/ (deployed to Cloudflare Pages by CI — no AWS)
```
Never commit `dist/`/`build/`, never use `--force` installs, never ship public source maps. **No AWS** for hosting or deployment (owner decision, ADR-011): the SPA and the public survey app are deployed to Cloudflare Pages; don't add S3/CloudFront/Amplify scripts or AWS SDKs.

## Architecture rules

- **Feature folders** — `src/features/<module>/` per spec (`routes.tsx`, `pages/`, `components/`, `hooks/`, `schemas.ts`). Shared primitives only in `src/components/ui/` (shadcn-owned) and charts in `src/components/charts/`.
- **Server state only through generated hooks** in `src/api/` (never edit generated files; never hand-write `fetch` for the API). Query keys come from orval; invalidate on mutations.
- **No business logic in the UI.** Scores, weights, rankings, readiness %, state transitions and permissions come from the API. The FE may format and visualise; it must never compute a score and send it to the server.
- **Permissions** — use `usePermission('gap:review')` / `<RequirePermission>` fed by `GET /v1/me`; also hide nav items for non-entitled modules and show the locked-module panel. Server enforcement is authoritative.
- **Auth** — access token in memory only (never `localStorage`/`sessionStorage`), silent refresh via `POST /v1/auth/refresh` (httpOnly cookie), single 401 interceptor.
- **Forms** — React Hook Form + Zod; labels on every field; errors linked via `aria-describedby`; disable submit while pending; server errors (problem+json) mapped to fields.
- **Routing** — lazy route modules, a 404 route, error boundaries per route, URL-synced tabs/filters (shareable links).
- **Public surfaces** (survey respondent, supplier invite, shared reports) are a separate lightweight entry with the minimal shell (see M08).

## UI rules (from `docs/revamp/02-design-system.md`)

- Tokens only — no raw hex, no inline `style={{…}}` for colour/spacing. Brand: slate `#475062` (primary) and amber `#D8882A` (accent, never as text on white).
- **RTL-safe**: logical Tailwind utilities only (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`), never `ml-/mr-/pl-/pr-/left-/right-`.
- **Dark mode** and **density** must work for every component; check in Storybook.
- **Every async view** has loading skeleton, empty state (explains + CTA) and error state (retry). Never render an empty `<div/>` while loading.
- **Charts**: use `ResiliChart` wrappers; fixed categorical slot order (ISO 26000 core subject → slot 1–7), one y-axis, legend for ≥ 2 series, "View as table" + downloads, text in text tokens. Never build tooltip HTML from unescaped user data.
- **i18n**: every string via `t()`; no string concatenation; ICU plurals; numbers/dates via `Intl`. Domain content (KC texts, templates) comes translated from the API.
- **Accessibility (WCAG 2.2 AA)**: keyboard operable, visible focus, 24×24 px targets, colour never the only signal, axe clean.

## Testing expectations

Component tests for interactive components (keyboard + screen-reader names), MSW-backed page tests for loading/empty/error states, Playwright e2e for the critical journeys of each module (sign-in, answer gap questions, submit for review, send survey, respond to survey, generate report), axe checks in e2e, Storybook stories for every `ui/` component.

## Conventions

- TypeScript strict, no `any`. Function components and hooks only. Named exports. Filenames kebab-case; components PascalCase.
- Conventional Commits (`feat(gap-analysis): …`). Reference the spec section in PRs ("Implements M04 §9").
- If implementation needs to deviate from a spec, update the spec in the same PR **in both repos** (`docs/revamp/` is mirrored in `CSR_BE`).
- Domain names follow the specs: *workspace* (legacy "agency"), *company*, *project*, *key consideration (KC)*, *issue of interest*, *core subject*, *documentation assessment*, *people*, *supplier / customer* (legacy "partners" is renamed).
